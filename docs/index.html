플레이 가능한 게임까지.

Stillbow는 움직이면 피하고, 멈추면 활을 쏘는 작은 궁수 게임입니다. 어떤 요청이 다음 결과로 이어졌는지, 핵심 단계만 따라가 봅니다.

01 시제품02 실행03 이미지04 적용05 개선06 자동 빌드

시작 전에

  • Godot 4.5.1과 로컬 파일을 수정·실행할 수 있는 AI 코딩 도구를 준비합니다.
  • 빈 프로젝트 폴더를 열고 아래 프롬프트를 차례로 요청합니다.
  • 각 단계의 결과를 확인한 뒤 다음 단계로 넘어갑니다.
  • 자동 빌드까지 따라 하려면 GitHub 계정과 GitHub CLI 로그인이 필요합니다.

프롬프트를 읽는 방법

짧은 인용문은 실제 사용자가 요청한 문장입니다. 처음 요구사항처럼 원문 전체를 보존하지 않은 부분은 따라 하기용 프롬프트로 다시 정리했습니다.

원본 대화 전체가 아닌 핵심 흐름입니다. 계정 이름·로컬 경로는 자신의 환경에 맞게 바꾸세요. AI가 만든 결과는 직접 실행해서 확인해야 합니다.

01

작은 시제품으로 규칙부터 만들기

처음부터 그래픽과 계정 기능을 만들지 않고, 이동·회피·정지 사격이 재미있게 연결되는지 확인했습니다. Archero 공식 스토어의 웨이브·강화·재시작 구조를 참고하되, 원작 자산은 복제하지 않았습니다.

따라 하기용 프롬프트 · 초기 요구사항 정리
Godot 4.5.1로 궁수 게임 시제품을 만들어줘. Archero를 참고하되 캐릭터와 배경은 처음에는 스프라이트 없이 도형으로 표현해. 로그인이나 회원가입 없이 실행하면 바로 플레이하게 해. 이동 중에는 회피하고 멈추면 가까운 적에게 자동 사격하도록 해. 적의 공격, 체력, 5개 웨이브, 웨이브 사이 강화 선택, 사망 후 재시작을 구현해. WASD/방향키와 화면 드래그를 지원하고 실제 실행해서 검증해.

결과: project.godot, main.tscn, main.gd와 기본 전투가 만들어졌습니다.

확인할 것
움직일 때는 사격하지 않는가? 멈추면 쏘는가? 적에게 맞으면 체력이 줄고, 죽으면 다시 시작할 수 있는가?
02

설명이 아니라 실행 화면 확인하기

프로젝트 파일이 생겼다는 것과 게임이 실행된다는 것은 별도로 확인했습니다.

따라 하기용 프롬프트 · 실행 요청 정리
완성된 시제품을 지금 데스크톱 게임 창으로 실행해줘. 실제 실행 여부를 확인하고 플레이 화면을 보여줘.

직접 실행: Godot에서 project.godot을 가져오고 F6을 누릅니다. WASD/방향키 또는 드래그로 이동하고, R로 재시작하며 P로 일시 정지합니다.

확인할 것
스크린샷뿐 아니라 실제 게임 창에서 움직여 봅니다. 실행하지 못했다면 원인과 필요한 환경부터 해결합니다.
03

게임에 맞는 이미지 만들기

도형으로 전투가 동작한 다음, 시각 자산을 요청했습니다.

실제 사용자 요청
캐릭터와 배경 이미지 만들어줘

AI는 게임 화면에 맞춰 청록 후드·금색 활의 궁수 투명 PNG와 빈 중앙을 가진 남색 석조 아레나를 각각 생성했습니다. 배경에는 UI·문자·적을 넣지 않아 전투 요소를 따로 그릴 수 있게 했습니다.

따라 하기용 프롬프트 · 이미지 조건을 구체화
위에서 내려다보는 궁수 게임용 이미지를 두 장 만들어줘. 1. 청록색 후드와 금색 활을 든 독창적인 궁수. 작은 화면에서도 구분되는 형태, 배경은 실제 투명 PNG. 2. 남색 석조 전투 아레나. 중앙은 비우고 장식은 경계에 두어 적과 탄환이 잘 보이게 해. 배경에 캐릭터, UI, 문자나 로고를 넣지 마. 두 이미지를 프로젝트에 저장하고 보여줘.

결과: assets/images/archer-v1.png, assets/images/arena-v1.png. 실제 이미지 생성 프롬프트도 저장했습니다.

확인할 것
캐릭터 배경에 알파 투명도가 있는가? 배경 중앙이 차분한가? 작은 크기로 봐도 활과 캐릭터가 구분되는가?
04

이미지를 실제 게임에 연결하기

실제 사용자 요청
적용해

이전 단계에서 만든 두 이미지를 사용하는 요청입니다. 플레이어 도형을 궁수로, 아레나 바닥을 배경으로 바꾸고, 적·탄환·UI와 전투 규칙은 유지했습니다.

따라 하기용 프롬프트 · 별도 대화에서도 쓸 수 있게
assets/images/archer-v1.png와 arena-v1.png를 현재 Godot 게임에 적용해줘. 궁수의 투명 여백을 제외해 적절한 크기로 표시하고 조준 방향에 맞춰 회전시켜. 기존 전투 기능과 UI를 유지하고 실제 실행 화면을 캡처해줘.
확인할 것
이미지 파일을 저장만 한 것이 아니라 게임에서 불러오는가? 조준 방향과 활 방향이 맞는가? 기존 기능이 계속 동작하는가?
05

화면을 보고 고치고, 다시 보기

실제 사용자 요청
니가 보고 계속 인간이 보기에 괜찮을 정도로 루프 돌면서 개선해

실행 → 캡처 → 화면 검토 → 수정 → 재실행을 반복했습니다. 첫 적용 화면에서 궁수가 작고 거칠게 보였으며 배경 원형 무늬가 가로로 늘어나 있었습니다.

실제 수정한 부분

  • 희미한 투명 픽셀을 제외하고 궁수를 높이 76픽셀로 표시했습니다.
  • 밉맵을 켜서 축소할 때 거친 세부를 줄였습니다.
  • 바닥 이미지는 원래 비율로 잘라 배치하고 위·아래 벽을 따로 표시했습니다.
  • 조준 방향으로 부드럽게 회전하고, 이동 경계를 안쪽으로 옮겨 벽에서 잘리지 않게 했습니다.
  • 배경을 조금 어둡게 해 밝은 적과 탄환이 구분되도록 했습니다.
멈출 기준
캐릭터가 잘리지 않고 배경이 왜곡되지 않으며, UI를 읽을 수 있고 적·탄환·플레이어를 구분할 수 있는가? 전투 동작 검사도 통과했는가?

아트는 한 방향의 정적 이미지입니다. 걷기 애니메이션과 방향별 그림은 아직 없습니다. 실제 Android 기기 플레이 검증도 별도 과제입니다.

06

main에 푸시하면 빌드되게 만들기

실제 사용자 요청
리포지터리 만들고 main 푸시 때 마다 안드로이드/PC 빌드 되도록

export_presets.cfg에 Android와 Windows 내보내기를 설정하고, GitHub Actions에서 Godot 4.5.1과 동일 버전 템플릿을 설치해 빌드하도록 구성했습니다. PC 대상은 이 프로젝트 실행 환경인 Windows x86_64입니다.

따라 하기용 프롬프트 · 빌드 조건을 명시
이 프로젝트의 GitHub 저장소를 만들고 main 푸시마다 Android APK와 Windows x86_64 ZIP을 빌드하도록 GitHub Actions를 구성해줘. Godot 4.5.1과 동일 버전의 export templates를 사용해. 리소스 가져오기와 기존 동작 검사를 먼저 실행해. Android는 테스트용 debug APK, Windows는 게임 데이터를 포함한 실행 파일로 만들어. 빌드 결과는 Actions 아티팩트로 업로드하고 키와 캐시는 커밋하지 마. 실제 push 후 두 빌드 결과를 확인하고 실패하면 수정해.

실제 첫 실행에서는 Windows가 성공했지만 Android SDK 설치가 실패했습니다. 설치 도구가 요청한 오래된 tools 패키지를 platform-tools로 바꾸고 다시 푸시했습니다. 워크플로 파일 작성 후 실제 결과를 확인하는 단계까지 포함하는 것이 핵심입니다.

다운로드: 아래 Actions에서 성공한 실행을 열고 Artifacts의 Stillbow-android-debug 또는 Stillbow-windows-x86_64를 받습니다. GitHub 로그인 필요, 보관 기간은 14일입니다.

APK의 범위
디버그 APK는 테스트 설치용입니다. Play Store 제출용 배포 서명이 아닙니다. 빌드마다 임시 키가 달라 이전 APK를 제거해야 새 APK를 설치할 수 있는 경우가 있습니다.

직접 이어서 해보기

소스를 내려받아 실행하거나, 위 프롬프트로 새 프로젝트를 만들어 비교해 보세요. GitHub CLI가 설치되어 있다면 다음 명령으로 소스를 받을 수 있습니다.
